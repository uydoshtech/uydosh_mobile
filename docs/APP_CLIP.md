# UyDosh App Clip — RoomPlan scanning for the Telegram Mini App

The `UyDoshAppClip` target lets a user scan a room with Apple RoomPlan
**without installing the full UyDosh app**. The Telegram Mini App creates a
scan session on the backend, opens the App Clip invocation URL, the clip
scans + uploads, and the user returns to Telegram.

```
Telegram Mini App                Backend                        App Clip
─────────────────                ───────                        ────────
save listing draft ──────────▶
create scan session ─────────▶  POST /listings/{id}/scan-sessions
                    ◀─────────  { scanSessionId, invocationUrl, expiresAt }
openLink(invocationUrl) ─────────────────────────────────────▶ launch
                                GET /scan-sessions/{id}  ◀──── validate
                                                               RoomPlan scan
                                POST .../uploads         ◀──── upload URLs
                                (PUT files)              ◀──── upload USDZ/JSON
                                POST .../complete        ◀──── mark done
read start_param=scan_{id} ◀─────────────────────────────────  t.me return link
```

## Project layout

The App Clip is **pure Swift/SwiftUI** — no Flutter, no CocoaPods (Flutter
cannot fit the App Clip size budget). It lives in the existing
`ios/Runner.xcodeproj` as a third target:

```
ios/
├── Shared/                     # compiled into UyDoshAppClip (reusable by Runner later)
│   ├── AppClipCore/            # AppClipConfig (domains, t.me links), ScanInvocation (URL parsing)
│   ├── API/                    # APIClient, ScanSessionAPI (live + mock), UploadService (URLSession + mock)
│   ├── Models/                 # ScanSession, ScanUploadResult, NormalizedRoom (versioned JSON schema)
│   └── RoomScanner/            # RoomPlanSupport, RoomScanCoordinator (RoomCaptureView wrapper),
│                               # MockRoomScanner, RoomExporter (USDZ + JSON), RoomNormalizer,
│                               # RoomScanArtifacts (exported files kept until upload succeeds)
├── UyDoshAppClip/
│   ├── UyDoshAppClipApp.swift  # @main, NSUserActivity handling
│   ├── AppClipRouter.swift     # AppClipScanState state machine + scan/upload orchestration
│   ├── Views/                  # RootView, ScanIntroView, ScanView (live RoomCaptureView),
│   │                           # ScanReviewView (SceneKit preview + snapshot),
│   │                           # UploadProgressView, ScanSuccessView, ScanErrorView
│   ├── Info.plist, UyDoshAppClip.entitlements
│   └── Localizable.xcstrings, InfoPlist.xcstrings   (en / ru / uz)
└── scripts/add_app_clip_target.rb   # regenerates the Xcode target + scheme
```

### Scan → upload flow (implemented)

- `AppClipRouter.startScan()` picks the scanner: real `RoomScanCoordinator`
  on LiDAR hardware, `MockRoomScanner` on the simulator. Both implement
  `RoomScanning`, so the flow is identical either way.
- Finish stops the capture session; RoomPlan post-processes; the coordinator
  exports **immediately** (USDZ via `CapturedRoom.export`, parametric with
  mesh fallback, plus versioned `NormalizedRoom` JSON) into a per-session
  temp dir — so the result can't be lost while navigating.
- The review screen renders the exported USDZ in SceneKit (orbit controls);
  its snapshot becomes the uploaded `preview` JPEG. Retry discards artifacts
  and rescans.
- Confirm uploads `room_json` + `room_usdz` (+ `preview`) with aggregate
  progress via `URLSessionUploadService` (`PUT` to backend-issued URLs with
  `X-Scan-Upload-Token`), then calls `complete`. Failures keep the artifacts
  on disk and offer retry; a background task keeps uploads alive briefly if
  the user backgrounds the clip.
- Floor area/height are computed from RoomPlan floor polygons and wall
  heights (`RoomNormalizer`), sent as metadata, and **never fabricated** —
  the backend independently computes full footprint metrics from the
  converted GLB (existing `computeRoomScanFootprintFromGlb` fallback), which
  is why the clip doesn't duplicate `ios/Runner/RoomScanMetricsComputer.swift`.

The target, groups, and shared scheme are **generated by
`ios/scripts/add_app_clip_target.rb`** (re-runnable; it picks up new files
under `ios/Shared` and `ios/UyDoshAppClip`):

```bash
ruby ios/scripts/add_app_clip_target.rb
```

- Bundle ID: `com.uydosh.app.Clip` (parent: `com.uydosh.app`)
- Deployment target: iOS 17.0 (same as Runner)
- The invocation domain is centralized in `Shared/AppClipCore/AppClipConfig.swift`
  (`scan.uydosh.uz` today; URL parsing is host-agnostic, so changing the
  domain is a one-line edit plus entitlement/AASA updates).

## IMPORTANT: not yet embedded in the Runner app

The App Clip is intentionally **not** added to Runner's "Embed App Clips"
build phase yet. Embedding makes `flutter build ipa` (and the
`release-testflight.yml` workflow, which manually provisions only
`com.uydosh.app`) require an App Clip provisioning profile and would break
TestFlight releases until App Store Connect + CI are prepared.

Until Phase 5, the App Clip runs standalone from its own Xcode scheme, which
is fully sufficient for development. Phase 5 adds:

1. Register bundle ID `com.uydosh.app.Clip` + App Clip capability in the
   developer portal; create an App Store provisioning profile for it.
2. Add the profile to `release-testflight.yml` signing and
   `ExportOptions-ci.plist`.
3. Add the "Embed App Clips" copy-files phase to Runner (destination
   `$(CONTENTS_FOLDER_PATH)/AppClips`) — a small extension of
   `add_app_clip_target.rb`.
4. Set the clip's `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` to match
   the parent app (`FLUTTER_BUILD_NAME` / `FLUTTER_BUILD_NUMBER` from
   `pubspec.yaml`).
5. Add `applinks:scan.uydosh.uz` to `Runner/Runner.entitlements` so the full
   app (when installed) intercepts the same URLs.

## Local testing

### Run from Xcode

1. Open `ios/Runner.xcworkspace`.
2. Select the **UyDoshAppClip** scheme.
3. Run on a simulator or device. The scheme already defines:

| Environment variable | Value | Meaning |
|---|---|---|
| `_XCAppClipURL` | `https://scan.uydosh.uz/s/demo1234` | Simulated invocation URL (standard Xcode mechanism; edit in Product ▸ Scheme ▸ Edit Scheme ▸ Run ▸ Arguments) |
| `SCAN_CLIP_MOCK` | `valid` | Use the mocked backend. Scenarios: `valid`, `expired`, `invalid` (404), `error` (network failure). Disable to hit the live API. |
| `SCAN_CLIP_FORCE_SUPPORTED` | `1` | Bypass the LiDAR check on the simulator (which has no LiDAR). Remove to test the unsupported-device screen. |
| `SCAN_CLIP_MOCK_UPLOAD_FAILURES` | `1` (disabled by default) | Number of times the mocked upload fails before succeeding — exercises the upload-retry path. |
| `SCAN_CLIP_AUTOPILOT` | `1` (set manually) | DEBUG-only: auto-advances ready → scan → finish → confirm, smoke-testing the whole pipeline hands-free (pairs with `SCAN_CLIP_MOCK`). |

### Run on a physical LiDAR iPhone

RoomPlan requires a LiDAR device (iPhone 12 Pro or newer Pro models). Select
the UyDoshAppClip scheme, pick your device, and run — automatic signing with
team `D5THR62Q33` handles the development profile. On LiDAR hardware the
real RoomPlan capture UI runs; keep `SCAN_CLIP_MOCK=valid` to scan for real
but skip the backend, or remove it to hit the live API.

### Command line (simulator)

```bash
ruby ios/scripts/add_app_clip_target.rb   # only after adding/removing files
xcodebuild -project ios/Runner.xcodeproj -scheme UyDoshAppClip \
  -configuration Debug -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
xcrun simctl install booted <DerivedData>/Build/Products/Debug-iphonesimulator/UyDoshAppClip.app
SIMCTL_CHILD__XCAppClipURL="https://scan.uydosh.uz/s/demo1234" \
SIMCTL_CHILD_SCAN_CLIP_MOCK=valid \
SIMCTL_CHILD_SCAN_CLIP_FORCE_SUPPORTED=1 \
xcrun simctl launch booted com.uydosh.app.Clip
```

### Test matrix

| Case | How |
|---|---|
| Happy path | `SCAN_CLIP_MOCK=valid` |
| Expired session | `SCAN_CLIP_MOCK=expired` |
| Invalid session (404) | `SCAN_CLIP_MOCK=invalid` |
| Backend/network error + retry | `SCAN_CLIP_MOCK=error`, then tap "Try again" |
| Missing/invalid invocation URL | Disable `_XCAppClipURL`, or set it to a non-`/s/...` URL |
| Unsupported device | Remove `SCAN_CLIP_FORCE_SUPPORTED` on simulator |
| Upload failure retry | Set `SCAN_CLIP_MOCK_UPLOAD_FAILURES=1` (mock upload fails once, then succeeds after "Try again") |

## Backend endpoints (implemented in uydosh_backend)

Implemented in `uydosh_backend` (`scanSessionService/Controller/Routes`,
migration `_0029_scan_sessions.js`); routes mount at the root (no `/api`
prefix). Sessions have a 1-hour TTL; tokens are
`crypto.randomBytes(12).toString('base64url')` (same scheme as
`telegram_bot_link_tokens`).

1. `POST /listings/{listingId}/scan-sessions` (Mini App, Telegram initData
   auth in body; owner only; 403 `lidar_room_scan_disabled` when the feature
   is switched off in admin settings) →
   `{ scanSessionId, invocationUrl, expiresAt }`
2. `GET /scan-sessions/{scanSessionId}` (no user auth — opaque short-lived
   id) → `{ scanSessionId, listingId, status, uploadToken?, expiresAt,
   roomScanGlbUrl?, pointCloudUrl? }`. `uploadToken` only while the session
   is active; GLB/USDZ URLs once `completed`. Also used by the Mini App to
   poll status.
3. `POST /scan-sessions/{scanSessionId}/uploads` (App Clip, `X-Scan-Upload-Token`)
   → `{ uploads: [{ type, uploadUrl, storageKey }] }` — upload URLs point at
   backend-tokenized `PUT /scan-sessions/{id}/files/{type}` endpoints today
   (storage is local disk on EC2); the contract is identical to S3
   pre-signed URLs, so storage can move later.
4. `PUT /scan-sessions/{scanSessionId}/files/{type}` (raw binary body; types
   `room_json` ≤10MB, `room_usdz` ≤60MB, `preview` ≤10MB).
5. `POST /scan-sessions/{scanSessionId}/complete` (App Clip, `X-Scan-Upload-Token`)
   → responds `{ status: "processing" }` immediately, then asynchronously
   reuses the existing `listingPhotoService.uploadRoomScan` pipeline
   (USDZ → stylized GLB via Blender/Convert3D → footprint metrics →
   listing columns), copies `room_scan.json` / `room_scan_preview.jpg` into
   the listing's image dir, and marks the session `completed` (or `failed`).

Status lifecycle: `created → uploading → processing → completed | failed`,
plus `expired` (TTL, checked lazily on every read).

Security properties: the invocation URL contains only an opaque short-lived
session id. No Telegram user ids in URLs; no authentication inside the App
Clip; uploads/completion additionally authorized by the separate
`uploadToken` (`X-Scan-Upload-Token` header).

The invocation base URL is `https://scan.uydosh.uz` by default and
overridable with the `SCAN_CLIP_INVOCATION_BASE` env var
(`src/config/scanSessionConfig.ts`).

## Telegram Mini App integration (implemented in uydoshtech.github.io)

- **Upsell:** after publishing a new "room offered" listing,
  `telegram-create.js` renders a "Add a 3D room plan" card on the success
  screen (`#scan-upsell` in `telegram/create.html`). On iOS it creates a
  scan session (`UyDosh.createListingScanSession`) and opens
  `invocationUrl` via `Telegram.WebApp.openLink()`; on other platforms it
  offers copying the scan link to open on an iPhone. Scanning is always
  optional — the regular success actions stay available, and the card hides
  itself when the backend reports `lidar_room_scan_disabled`.
- **Polling:** while the create page stays open, it polls
  `GET /scan-sessions/{id}` every 4s (only while visible, stopping on any
  terminal status) and swaps the button to "View 3D plan" on completion.
- **Return leg:** after upload the clip opens
  `https://t.me/uydosh_bot/app?startapp=scan_{scanSessionId}`
  (`AppClipConfig.returnToTelegramURL`). `uydosh-mini-app.js`
  (`redirectFromMiniAppStartParam` → `restoreScanSessionFromStartParam`)
  recognizes the `scan_` start_param, shows a blocking "building the 3D
  plan…" overlay, polls the session, and redirects to
  `listing.html?id={listingId}&mini=1&view=3d` (the existing GLB viewer in
  `listing-detail-roomscan.js`) once completed. Failed/expired sessions get
  a message plus a plain "open listing" fallback.

## Associated Domains / AASA

Entitlements already prepared:

- App Clip (`ios/UyDoshAppClip/UyDoshAppClip.entitlements`):
  `appclips:scan.uydosh.uz`
- Full app (Phase 5): add `applinks:scan.uydosh.uz` to
  `ios/Runner/Runner.entitlements`.

The server at `scan.uydosh.uz` must serve
`https://scan.uydosh.uz/.well-known/apple-app-site-association`
(content type `application/json`, no redirects):

```json
{
  "appclips": {
    "apps": ["TEAM_ID.APP_CLIP_BUNDLE_ID"]
  },
  "applinks": {
    "details": [
      {
        "appIDs": ["TEAM_ID.FULL_APP_BUNDLE_ID"],
        "components": [
          { "/": "/s/*" }
        ]
      }
    ]
  }
}
```

Replace `TEAM_ID`, `APP_CLIP_BUNDLE_ID` (the clip's bundle id), and
`FULL_APP_BUNDLE_ID` (the parent app's bundle id) with the real values used
by your signing setup. The existing AASA files (backend `deepLinkRoutes.ts`
for `api.uydosh.com`, and `uydoshtech.github.io/.well-known/`) are separate
and unchanged.

## Beta App Clip Experience (App Store Connect, Phase 5)

After a build containing the embedded App Clip is uploaded to TestFlight:

1. App Store Connect ▸ your app ▸ TestFlight ▸ the build ▸ **App Clip**.
2. Add a **Beta App Clip Experience** (TestFlight-only invocation) with URL
   prefix `https://scan.uydosh.uz/s/`.
3. Testers with TestFlight installed can then invoke the clip from that URL
   (e.g. via the Mini App upsell screen) without the AASA file being live yet.
4. For production, configure an Advanced App Clip Experience with the same
   URL prefix, title, and image; the AASA file must be live on the domain.
